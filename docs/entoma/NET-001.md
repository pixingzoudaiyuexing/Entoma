Owner approved removing only the old CI-signed test installation and its local

gvisor/ON, system/ON, mixed/ON. The actual private TUN listener stack and Android

uses platform/default trust, no explicit proxy, and new core connection IDs must

Detailed preserved logs/artifacts are in `dist/post-device/0c77d0b8`. Initial
permission-wait start errors, a rejected IPv4 diagnostic producing HTTP400, and
failed test builds are retained and are not classified as successful network tests.

The pinned FD-name condition was inverted. Name correction alone was falsified
as sufficient. The final Android-only policy identifies the live TUN device,
strictly binds its kernel TCP forwarder, and uses the pinned System stack's
wildcard-local-address mode. Bind/name failure rejects startup; there is no
unbound wildcard fallback. This preserves NAT/rules/outbound and the mixed default.
The earlier TUN FD is registered for cleanup immediately after creation, before
name validation. Failed Mixed startup also closes any System listeners created
before the UDP stack existed. Both with/without-gvisor build variants are retained.

AOSP Android 10's address-removal socket destruction includes listening sockets
bound to the removed address. UID-range cleanup is a different path and does not
support the claim that protecting an outbound socket fixes this listener. The
actual Huawei netd event ordering was not directly traced: the address-removal
mechanism is an evidence-supported explanation, not a universal ROM root-cause
claim. An unnecessary socket-control/dependency-overlay experiment was discarded
before committing; no new module replacement, dependency or global cache edit ships.

## Build and reproduce

Run the normal pinned bootstrap first. Ordinary builds contain neither the Go
acceptance exports nor the Dart harness/LAN reachability control. Engineering
builds explicitly require Go tags `with_gvisor,entoma_acceptance`, Gradle property
`entomaNetworkAcceptance=true`, and Dart define `ENTOMA_NETWORK_ACCEPTANCE=true`.
Optional Dart defines select `ENTOMA_NETWORK_CELL=mixed:true`,
`ENTOMA_NETWORK_CYCLES=100`, and `ENTOMA_NETWORK_PROBE_WINDOW=0` for rapid stress.
No password, token, raw subscription or raw core DTO is printed.

Compile `tool/android_acceptance/EntomaHttpsProbe.java` with JDK17 targeting Java8,
convert its class to DEX with SDK d8, then push only this owned fixture to
`/data/local/tmp/entoma-https-probe.dex`. Start the collector before opening Entoma:

```sh
python3 tool/android_acceptance/collect.py --adb /path/to/adb --source SOURCE_SHA --output NEW_EVIDENCE_FILE.json
```

The collector refuses to overwrite old evidence and never starts UI, clears
logcat, logs credentials or writes server data. Shell timeout/unavailability must
produce an explicit failed record. A complete event alone does not prove PASS:
verify all expected cell/cycle records and the default-TLS HTTP/status/node checks.
LAN testing requires the same phone Wi-Fi address to accept a temporary,
engineering-only control listener while rejecting the actual TUN forwarder port.
Control sockets immediately close without reading data or accepting commands;
all are closed before harness return. No negative result without a reachable
control is promoted to a LAN-isolation pass.

## Final six-cell evidence (32cf941)

The final device matrix produced exactly 18 unique app probes and 18 matching
adb-shell probes. All returned default-TLS HTTPS 200; every app connection used
TUN inbound and the selected test node, without DIRECT. All twelve mixed/system
cycles had a reachable temporary Wi-Fi control and a refused TUN forwarder
port. gvisor has no kernel forwarder and is excluded from those twelve checks.
All native stack/HTTP-proxy labels matched actual readback. Final stop recorded
zero VPN networks, closed owned FD, inactive native TUN, and 18 starts/18 stops.
Background label in that matrix was resumed, so it is not a background pass.
Sending the UI Home between matrix cycles paused further harness progress;
returning to Entoma resumed the matrix without a network probe failure. This
observation is retained separately from a stable-connection background test.

A later native-failure fixture reaches TUN-name ioctl rejection using only an
owned pipe FD, then checks EBADF. It never establishes a VPN, touches account
records or modifies real subscription configuration. Final product SHA/CI and
fixture/device acceptance are recorded after their exact builds complete.

Embedded review adjudication: accepted the FD-ownership-before-validation and
explicit empty-name error fixes; added defensive nil checks. Early registration
of a partially constructed stack is intentional so constructor defer owns its
cleanup. Go net.Listener.Close is idempotent with respect to its OS descriptor;
reverting ownership until Start success would reintroduce leaks. Unrelated
platform cleanup and broad firmware testing remain outside this Android fix.
